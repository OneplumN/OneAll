# 旧平台业务逻辑补充审计

本文件用于把旧平台已有业务逻辑和当前 OneAll 重构版本做差距对齐。旧平台只作为业务事实来源，不作为页面照抄来源。

## 1. 总体判断

当前重构已经覆盖了主导航、资产中心方向、首批 API 契约、权限矩阵、告警 DSL、工单状态机和 Go API 骨架。但旧平台里仍有大量可执行业务动作没有完整迁入。

需要补充的重点不是继续增加菜单，而是把已有页面做成闭环：

- 表单校验
- 提交 / 编辑 / 删除 / 启停
- 批量操作
- 异步任务轮询
- 权限拦截
- 审计、通知、变更记录
- API 与数据库持久化

## 2. 资产中心

当前已收敛为“模型资产 / 模型管理 / 同步任务 / 导入导出记录”，方向正确。

需要补充：

| 缺口 | 旧平台已有逻辑 | 当前状态 | 优先级 |
| --- | --- | --- | --- |
| 模型字段配置保存 | 字段配置 Drawer，保存字段、唯一键、展示字段 | 已完成前端和 API 闭环，平台默认模型和自定义模型均可编辑；已补字段禁用、已使用字段禁止删除；字段排序不放行内操作 | P0 |
| 模型资产手动新增 | 根据当前模型字段动态生成表单，校验唯一键 | 未闭环 | P0 |
| 模型资产导入 | CSV 模板下载、预览、最多 500 条、错误行提示、提交导入 | 当前主数据页不做导入，需放导入导出记录或模型管理低频入口 | P1 |
| 模型资产导出 | 按当前模型字段导出 CSV | 未实现 | P2 |
| 同步预览 | 预览新增、更新、删除、失败样本 | 已完成目标模型选择、预览、执行、历史和写回模型资产页 | P0 |
| 同步失败处理 | 同步 run 详情、重试、恢复 | API/页面不足 | P1 |
| 资产详情 | 旧平台有详情弹窗和关系图加载 | 当前保留属性/变更记录；独立关系不进入首版 | P1 |
| 工单纳管主机状态 | 单行/批量在线状态切换 | 当前只展示 | P1 |

保留边界：

- 不恢复旧平台固定资产导航，如域名资产、主机资产、应用资产。
- 不做独立模型关系和业务拓扑。
- 不在模型资产页放新增、导入、导出、配置、同步按钮。

## 8. 权限与路由保护

旧平台的路由保护包括：

- 未登录跳登录页
- 进入页面前获取 profile
- modulePermission 校验
- permission 校验
- 无权限跳 403
- 网络异常时不误判为无权限
- 页面 title 根据导航自动生成

当前重构需要补充：

| 缺口 | 当前状态 | 优先级 |
| --- | --- | --- |
| 前端真实路由守卫 | 原型 hash 路由只有角色切换 | P0 |
| API 角色权限统一拦截 | 部分接口有测试，需扩大到所有管理动作 | P0 |
| 403 页面和 fallback | 不完整 | P1 |
| 权限失败用户反馈 | 不完整 | P1 |

## 9. 建议落地顺序

第一批先补“能形成闭环”的能力：

1. 模型管理：新建模型、编辑字段、唯一键、主显示字段、保存后模型资产可见。
2. 工单申请：拨测监控申请表单、提交、审批、驳回、重新提交、执行日志。
3. 监控策略：新建、编辑、启停、删除、克隆、通知对象。
4. 一次性检验：多探针选择、批量提交、轮询、结果详情。
5. 系统设置：用户/角色/权限树、数据源/凭据 CRUD 和测试。
6. 探针节点：健康摘要、运行态、指标历史、配置版本。

第二批补通知、告警和恢复：

1. 资产同步失败恢复和 run 详情。
2. 通知渠道配置、测试、模板管理。
3. 告警详情上下文、关闭、批量关闭。
4. 审计日志详情和筛选。

## 10. 当前结论

旧平台里值得迁入的不是“更多菜单”，而是操作闭环。当前重构最需要补的是：

- 模型配置闭环
- 监控策略闭环
- 拨测申请工单闭环
- 一次性检测轮询闭环
- 用户/权限/数据源/凭据管理闭环

这些补齐后，OneAll 才能从高保真原型进入可验收业务系统。
